# Making Aetherion maps in the map editor

**Standing rule (the user, 2026-11-02):** every new map is made as a **map file** the user can open and see in a real
map editor: `game/maps/<id>/map.json`, edited in Godot with the Aetherion Map Editor plugin. Not generated by code
at load, not a one-off script. The user watches the progress (pictures as you go), QAs it personally, and points at
the small details that matter by **pinning notes on the map**. A script may lay out a first draft (see
`work/hf/build_hidden_forest.py`), but once written the map file is the source: edit the file, or have the user edit it
in the editor.

Full reference for people: `docs/MAP_EDITOR.md`. Bots: the `aetherion-waypoints` skill.

**Standing rule (the user, 2026-11-02): uneven ground is always Terrain3D, together with the map editor.** Terrain3D
(`game/addons/terrain_3d/`, built from the user's source at `A:\Python\terrain`, MIT) draws, sculpts, paints and plants
the ground; the map file's pieces stand on it. Never write a custom heightfield or terrain mesh. The map header's
`"terrain"` block points at its data (`game/maps/<id>/terrain/`); saving the map bakes the heights to
`terrain/heights.res`, which the game collides with on every machine (servers need no extension), the bots survey and
`ground_height()` reads. Code: `game/src/world/maps/authored/map_terrain.gd` (r27). Rebuild the binaries with
`python -m SCons` in `A:\Python\terrain` (Windows: MSVC; Android: `platform=android arch=arm64` with
`ANDROID_NDK_ROOT=A:\Python\re\android-ndk\android-ndk-r28c`), then copy `project/addons/terrain_3d` into `game/addons/`.

## The pieces

| Path | What |
|---|---|
| `game/maps/<id>/map.json` | **The map.** Header (name, code, bounds, levels, level_height, night_only, teams) and pieces |
| `game/maps/<id>/qa.json` | QA notes pinned in the editor: `{map, notes: [{id, at, text, status, piece, author, reply, created}]}` |
| `game/src/world/maps/authored/map_doc.gd` | The format: pieces to brushes and entities, load / save, checks, the catalogue (doc comment = the format spec) |
| `game/src/world/maps/authored/json_layout.gd` | The game's side: builds the map with `addons/aetherion_map/map_scene.gd`, surveys it for bots |
| `game/src/world/maps/authored/authored_layout.gd` | Shared with Freight Delight: spawns, stairs, walk grid per level, minimap |
| `game/addons/aetherion_mapedit/` | The Godot editor plugin (Maps dock, 3D toolbar, piece gizmos, QA notes, self-test) |
| `game/editor/maps/<id>.tscn` | The map's editor scene (a shell; the pieces come from the file). Not exported |
| `tools/map_plan.py` | Plan pictures with every piece's id and the notes: `work/maps/<id>/plan.png`, `plan_L2.png`... |
| `tools/make_jungle_textures.py` | Draws texture sets (`jungle/...`, built on `tools/make_freight_textures.py`) and adds them to `surfaces.json` |

A map file is registered everywhere by itself: map lists, names, Deathmatch rules (`modes`, `teams`, `field_optional`,
`night_only`), waypoint codes (`code`). Nothing else to edit.

## The format in one screen

Metres; x east, z south, y up; `yaw` is a compass bearing (0 north, 90 east). Every piece has `id` (unique, readable:
`hall_s`, `h3_stair`), `type`, `layer`, optional `name`, `note`, `tex_size`. Textures are `folder/name` under
`game/assets/maps/textures` (see `work/freight_textures.png` for the freight set; `jungle/` has the Hidden Forest's
stone, stucco, carvings and wood).

- `floor` at = centre with y = **top**; size [w, d]; t. `box` at = centre of the **base**; size [w, h, d]; tilt [pitch,
  roll] for roofs and slopes. `poly` (any outline), `column`, `ramp` (a solid wedge).
- `wall` from [x, z] to [x, z], y, h, t; `mat` both faces, **`mat2` = the face on your left walking from -> to** (walls
  run counter-clockwise round a building: left = inside; clockwise: left = outside). `openings` [{at (metres from
  `from` to the centre), w, h, sill, door?}]: openings at different heights may share x (a door below, a window above).
- `stairs` at = the foot (middle of the first riser, on the lower floor), yaw = the way up, rise, w; steps drawn, an
  invisible clip ramp is walked; bots link the floors at its ends.
- `light` (kind bulb/tube/lamp/flood/street/down/candle, color, energy, range, fault), `spawn` (team 1-3, yaw, for),
  `landmark` (name on the SmarTab map), `spot` (hide/snipe/cover for bots), `prop` (a model library name, physics).
- `solid: false` = drawn only (signs, wires, backdrop). `freight/clip` = invisible, stops bodies (the play area's edge).
  Signs and banners (`fit` in surfaces.json) cover their face once instead of tiling.

## Making a map (the procedure)

1. **Agree the brief** (theme, mode, team count and size, rough size, floors), then sketch the plan on a 5 m grid:
   spawns far apart, three or so lanes, cover between, sightlines, the second floor's ways up. Design the map yourself;
   do not recreate a map from another game.
2. **Create it**: Maps dock > New map in Godot, or write `game/maps/<id>/map.json` with the header and a first piece.
   Pick a two-letter `code`.
3. **Build in stages**, each one looked at before the next:
   ground, bounds (clip walls) and spawns; the main structures; the secondary buildings; cover and props; lights,
   landmarks and bot spots; a backdrop past the play area (`solid: false` blocks, a wider ground) so the edge is not the
   end of the world. After each stage:
   ```bash
   python -I tools/map_plan.py <id>
   godot --headless --path game -s res://tools/map_doc_test.gd -- --map=<id>
   godot --path game res://tools/map_preview.tscn -- --map=<id> --out=work/<run>/stageN --views=none --times=450 --size=1600x900 --cams="air:52,42,56,0,0,0;street:-14,1.7,25,10,1.5,25"
   ```
   Look at every picture yourself, fix what is wrong, then **send the plan and two or three views with SendUserFile**
   (the user follows from their phone too). `--times=450` is midday (matches start at night: `--times=30` for night).
   A camera is `name:x,y,z,tx,ty,tz` (eye, then the point looked at).
4. **Bots**: `bash tools/bake_botnav.sh <id>`, then the strict check (`--wpqa`). Coverage 100% (or explain the rest), all
   routes found, no edge failing, no node blocked, no orphans. Then a match with `--navwatch`. See `aetherion-waypoints`.
5. **Play it**: the editor's Play button, or
   `godot --path game -- --host --game_mode=deathmatch --map=<id> --bots=11 --autostart=1`.
6. Tell the user it is ready to QA in the editor: open `game/` in Godot 4.7, Maps dock, double-click the map.

## The QA loop (the user's notes)

1. Read `game/maps/<id>/qa.json`. Each note has where it is (`at`), the piece it was pinned on (`piece`), the text.
2. Look before changing: render a camera at the note (`--cams="n3:<x+3>,<y+1.7>,<z+3>,<x>,<y+0.5>,<z>"`) and read the
   piece in `map.json`. Ask when the note is ambiguous; otherwise fix exactly what it says, nothing broader.
3. Edit `map.json` (the open editor reloads it by itself when it has no unsaved edits). Keep ids stable.
4. Answer in the note: set `status` to `fixed` (or `question` / `wontfix` with the reason) and write `reply` (what changed,
   in numbers: "moved 0.2 m north, the step is now 0.17 m"). Keep the note; the user closes it.
5. Send a before / after picture of each spot. Re-bake the bots when geometry changed.

## Checks before saying it works

- `map_doc_test --map=<id>`: loads, no problems, the text round trip, builds, spawns, a walk grid per level, every
  full-storey stair linked.
- Editor self-test (in the real editor, pictures in the folder):
  `AETHERION_MAPEDIT_TEST=<abs folder> AETHERION_MAPEDIT_MAP=<id> godot --path game -e` (8 checks; restores the files).
- `--wpqa` numbers and pictures, a `--navwatch` match, `bash tools/check.sh` (196 scripts compile).
- Real pictures in the game, day and night. A green check is not a picture: look at them.

## Gotchas found making the first maps (r26, r27)

- A stair's foot point is 0.7 m + half a tread in front of the first riser: keep about 1.5 m clear there, or bots
  cannot get on (the strict check reports the stair node "blocked" and the floor above as orphans).
- Walls going clockwise round a house put `mat2` outside. Check the outside colour in a picture.
- The editor saves pieces grouped by layer: the first save from the editor reorders the file (same pieces).
- Ctrl+S in a map editor scene writes the map file and keeps the pieces out of the `.tscn`.
- New textures: a script like `tools/make_jungle_textures.py` (or a PNG + a `surfaces.json` entry), then `bash tools/import.sh`.
  Godot rewrites thousands of `.import` files when the editor or an import runs: revert the churn, keep new ones.
- `tools/map_plan.py` writes to `work/maps/<id>/` (outside `game/`, so the pictures are not imported into the game).
- The worktree needs `game/.godot` (copy it from a worktree on the same version, 5 GB) and the polyhaven folder
  (a junction) before Godot can run.
- `godot` = `A:\Installer\Godot_v4.7.2-stable_win64\Godot_v4.7.2-stable_win64_console.exe`.
